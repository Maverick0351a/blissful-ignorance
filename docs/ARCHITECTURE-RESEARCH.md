# Small non-LLM learning agents: architecture research

Checked 2026-10-04 (America/Los_Angeles). Research only: no model, package, repository, or dataset was downloaded, installed, or executed. Project requirements are eight independent creatures, random initial weights, separate lifetime experience, local observations, and a persistent shared world.

**Recommendation:** keep the compact observation encoder + 128-unit LSTM + recurrent PPO as the first learning baseline. Test a MinGRU policy next under the same tasks and budgets. Hugging Face contains small non-LLM policies and useful survival-game references, but their published trained weights already contain learned skills. Use architecture/training ideas for randomly initialized creatures; importing checkpoints would change the blank-slate experiment.

## Platform and evidence boundaries

[JAX's current platform table](https://docs.jax.dev/en/latest/installation.html#supported-platforms) lists native Windows NVIDIA GPU support as unavailable and WSL2 as experimental. This affects Craftax, MA-Craftax, ReMDM, and the author DreamerV3 stack. CPU support is distinct from GPU support. [PufferLib 5.0's build script](https://github.com/PufferAI/PufferLib/blob/5.0/build.sh) branches for Linux/macOS and has no native Windows branch. That is a concrete integration obstacle, not proof that porting is impossible. Existing PyTorch recurrent layers offer the lowest dependency change for the initial Windows prototype.

No candidate was benchmarked on this project or on a 16 GB laptop GPU. Parameter counts, checkpoint bytes, published GPU throughput, and environment-frame efficiency cannot establish local training speed, memory use, or useful lifelong learning. HF cards are publisher claims; listed evaluations were not independently reproduced.

## Proposed first brain and decision gate

Use a trainable encoder for the actually visible 9 × 9 tile patch, concatenate own needs/inventory, previous action, and locally received symbols, then feed the 128-unit LSTM and categorical action/value heads. Keep each creature's parameters, optimizer, recurrent state, rollout data, and random state separate. Persist those states with the world. Reset recurrent state at actual lifecycle boundaries, not at every PPO rollout chunk; preserve sequence order and episode masks in training. This is a proposed design, not measured performance.

The next architecture comparison should change the recurrence first: LSTM-128 versus a similarly sized GRU/MinGRU, with the same encoder, rewards, action legality, observation limits, training seeds, and held-out maps. Record both equal-transition and equal-wall-time results because faster recurrence can otherwise hide poorer learning. Predeclare a compute cap and compare success, survival/resource outcomes, seed variance, forgetting after task changes, achieved simulation speed, update latency, and peak memory. Retain the simpler baseline unless improvement repeats across held-out seeds within that cap.

If recurrent PPO fails after implementation/reward/observation checks, test a compact learned world model as a separate experiment. Use only the creature's real experience for named residents; disposable benchmark worlds remain clearly separate. Check imagined predictions against real held-out transitions and report calibration/confident errors before using imagination as a learning advantage. Do not select Dreamer merely because it is a world model.

Communication and curiosity require separate controls: shuffled/silenced symbols must reduce relevant held-out task performance before calling signals meaningful; curiosity must improve exploration or learning without degrading survival through stochastic distractions. None of these architectures promises culture, parenting, general intelligence, or creator recognition.

Additional lead, not an implementation recommendation: [Improving Transformer World Models for Data-Efficient RL](https://huggingface.co/papers/2502.01591) reports better Craftax-Classic sample efficiency than its DreamerV3 comparison. It is useful evidence that world-model design matters, but benchmark results do not select a native Windows implementation or prove transfer to this persistent multi-agent world.

## Fruit fly brains: a useful experimental branch

Follow-up checked 2026-10-04. Fruit fly connectomes and working neural simulators are real, relevant alternatives for non-LLM creatures. They supply different parts of the problem:

| Resource | Verified scope and project fit |
| --- | --- |
| [FlyWire](https://codex.flywire.ai/) and [release guidelines](https://join.flywire.ai/guidelines) | An adult female brain wiring dataset, approximately 140,000 neurons and tens of millions of anatomical synapses. It specifies structure, not a complete executable learning rule, sensory encoder, or game-action decoder. The public data license is CC BY-NC 4.0. |
| [MaleCNS](https://male-cns.janelia.org/) and [downloads](https://male-cns.janelia.org/download/) | A newer whole male central nervous system resource; v1.0 released June 2026, with a September 2026 paper. Data is CC BY, separately from any simulator license. It includes annotations, neurotransmitter predictions, and connection strengths. More complete anatomy still does not provide validated lifelong learning dynamics. |
| [Eon's official fly-brain code](https://github.com/eonsystemspbc/fly-brain) | A whole-brain leaky integrate-and-fire simulator based on Shiu et al., with neuron activation/silencing and spike propagation across several backends. Its roughly 5M modeled weighted connections aggregate anatomical synapses; these counts must not be conflated. Main code is GPL-2.0-or-later; original Shiu Brian2 materials retain MIT. Its documented setup is Ubuntu under WSL2/CUDA 12, not tested native Windows. |
| [Eon's embodied fly report](https://eon.systems/updates/embodied-brain-emulation) and [FlyGym](https://github.com/NeLy-EPFL/flygym) | A genuine brain–body demonstration and a separate Apache-2.0 biomechanical/sensory simulation framework. Eon explicitly reports that internal state, plasticity, and learning are largely missing, and that sensory/descending-neuron mappings were hand chosen. FlyGym supplies body/senses/controller infrastructure, not an autonomous lifetime-learning brain. Its March 2026 API rewrite also makes version matching necessary. |
| [Mushroom-body learning paper](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1009205) and [author code](https://github.com/alitwinkumar/jiang_litwin-kumar_mb_rnn) | A concrete biological learning reference: sparse sensory representations, dopamine-gated plastic synapses, and output circuitry. Author code is GPL-3.0. The paper's method first optimizes circuitry producing learning signals, then tests fast plasticity on new tasks; it is not evidence that an arbitrary unoptimized circuit learns everything from birth. |

**Assessment:** a fly brain can be adapted as a resident controller, but it needs an explicit local sensory mapping, action readout, reward/internal-state signals, and a plasticity rule. Those engineering choices can dominate behavior. Wiring anatomy supplies a strong biological prior; it does not recover a fly's complete mind or prove consciousness. Neural activity, walking, or an attractive visualization alone does not demonstrate learning.

Whole-brain spiking dynamics are also not comparable to an ANN by neuron count. The reviewed Eon implementations use 0.1 ms neural timesteps: 10,000 neural updates per simulated second, before embodiment. Eight independently plastic brains require separate learned weights and dynamic states. Shared immutable topology is possible, but local memory, throughput, and accelerated-world fit require measurement. No such measurement was performed.

The most practical initial fly-inspired trial is a small mushroom-body associative learner: for example, a proposed 256–1,024-unit sparse expansion, a few output channels, eligibility traces, and reward-modulated plasticity. This is an engineered simplification, not a downloaded whole-fly brain. Start with neutral weights and each creature's own experiences; compare it against recurrent PPO on learning which of two unfamiliar local cues predicts food, then reverse the cue meanings and test retention. Include frozen-plasticity and shuffled-reward controls, identical held-out seeds/interaction budgets, and an equal-wall-time comparison. Use a separate named brain type so the experiment stays inspectable.

Keep recurrent PPO as the first general action-learning baseline. If the associative trial works, evaluate it as an optional fast-memory module or alternative controller before attempting a whole-connectome creature. A whole-brain trial should begin with one disposable agent and a narrow task, then measure cost and causal contribution against a connectivity-shuffled control. This remains a research proposal; no fruit fly data or code was downloaded, installed, or run.

## Lifelong growth beyond a fixed small policy

Follow-up checked 2026-10-04. Five additional primary-source families address different constraints. The first recurrent controller should be a replaceable starting point, with identity and lifetime history independent of its network size. A network that continues receiving updates can still lose the ability to learn; a bigger network alone does not solve that.

| Mechanism and source | Evidence, limitation, and fit |
| --- | --- |
| [Continual backpropagation: author code](https://github.com/shibhansh/loss-of-plasticity) | MIT code accompanies the 2024 Nature study of loss of plasticity, including PPO experiments. It continually refreshes a small fraction of mature, low-utility units to preserve learning responsiveness. It maintains capacity rather than growing it. Original experiments were tested on Ubuntu/Python 3.8; our recurrent policy and Windows runtime need separate validation. First compare it in the encoder, not by arbitrarily replacing LSTM memory cells. |
| [NEAT-Python](https://github.com/CodeReclaimers/neat-python) | BSD-3-Clause, primarily standard-library Python; documented support includes Python 3.11. Evolves both topology and parameters by adding/changing nodes and connections. Good reference for expandable architecture genes and later lineage experiments. Standard NEAT selects a population across generations: it does not automatically make one persistent creature learn during its life. Population evaluation can dominate cost. |
| [POET / Enhanced POET: author code](https://github.com/uber-research/poet) | Apache-2.0 implementation coevolves challenge–solver populations and uses transfers between solutions. Useful design precedent for generating diverse learnable challenges. The older Fiber/Gym/shell-based stack needs compatibility work; it is not a plug-in for this custom world. Its cross-agent transfers change the own-experience rule, so borrow challenge generation separately and keep named residents' experiences separate. |
| [Differentiable plasticity: author code](https://github.com/uber-research/differentiable-plasticity) | Learns parameters of fast synaptic adaptation through gradient-based training, including pattern memory and maze experiments. A concrete option for the proposed associative-memory layer. Author code uses the Uber Non-Commercial License and old PyTorch-era examples; it is not permissively licensed reusable code. Learned plasticity rules require a training process and do not emerge merely by adding a Hebbian trace. |
| [Net2Net: author publication](https://research.google/pubs/net2net-accelerating-learning-via-knowledge-transfer/) | Function-preserving transformations can widen/deepen supported networks while reusing their learned function. Useful precedent for capacity expansion without restarting identity or learning. The reported results concern particular feedforward networks; they do not establish a correct LSTM-state/optimizer migration or indefinite improvement for this game. A native modern implementation is not supplied by this publication page. |

**Recommended layered design:** independent resident state and weights; an interchangeable versioned brain; expandable own-observation memory; optional fast plastic memory and learned world model; reusable learned skills; and controlled capacity-growth operations. Add one mechanism at a time so improvements remain attributable. [The proposed learning architecture](LEARNING-ARCHITECTURE.md) specifies these boundaries without changing implementation.

The strongest ceilings often live outside network size. A fixed action vocabulary prevents expressing additional kinds of behavior; a static world limits what can be discovered; observations bound available evidence; rewards can train shortcuts; forgetting can erase earlier skills; compute limits experience and experiments. Observation/action schemas and world mechanics can be extended explicitly. Increasing visible information must remain a designed sensory change, never a silent gift of hidden world state. Rewards and curiosity signals remain engineered incentives whose effects need controls.

Individual learning modifies a resident through its own experience. Evolution selects/mutates heritable designs across reproduction or a separate experimental population. Enlarging the same resident's network is capacity growth. These are three different processes, and each needs its own history and evaluation. No learned weights or experiences are automatically copied into children or other named residents.

The first growth evidence should be a changing-task sequence: learn food gathering, add a delayed dependency, reverse cue meanings, then revisit earlier tasks. Compare the fixed baseline, memory addition, plasticity maintenance, and a declared capacity-growth condition under identical held-out seeds and both equal-experience/equal-wall-time budgets. Record new-task learning speed, retained old skills, generalization, memory/latency, and all failed runs. Freeze numerical success and retention margins before execution. Growth passes only when added capacity or memory helps repeated new tasks while preserving earlier competence within the agreed compute budget.

Finite runtime, memory, and disk budgets make the experiment recoverable; they can be revised as evidence and hardware change. The design can avoid a permanently fixed 128-unit ceiling and a single permanently fixed brain architecture. No current source establishes that this combination will grow into general intelligence or capability without limit.
