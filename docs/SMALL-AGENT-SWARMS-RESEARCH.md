## Five candidates with different jobs

### 1. Continual backpropagation: maintain the ability to learn

**Learning algorithm, not a new brain architecture.** Continual backpropagation selectively replaces low-utility mature units while ordinary backpropagation continues. The Nature study distinguishes loss of plasticity—failing to acquire new knowledge—from forgetting old knowledge. Its supervised and PPO results support studying long lifetimes, not assuming this fixes starvation. [Paper](https://www.nature.com/articles/s41586-024-07711-7), [author code, MIT](https://github.com/shibhansh/loss-of-plasticity).

Apply first to a feedforward layer, not arbitrary LSTM gates. Each resident needs private utility/age counters, replacement RNG, weights and optimizer state; replacing units must handle corresponding optimizer moments and target-network updates. This is a moderate implementation change. It supplies neither episodic recall nor curiosity, and careless replacement can erase useful behavior. CPU/GPU PyTorch training is plausible; the original reproduction targets older Ubuntu/Python packages. The repository is a research implementation, with no current maintenance cadence verified.

### 2. E-prop with adaptive spiking recurrence: local online credit

**Neural architecture plus learning rule.** E-prop combines local synaptic eligibility traces with neuron-level learning signals, approximating temporal gradients without ordinary backpropagation through time. The paper includes reward-based Atari learning. This is a stronger local-plasticity candidate than importing a whole fly connectome and assuming biological wiring teaches farming. [Author-hosted paper](https://igi-web.tugraz.at/PDF/248.pdf), [official code](https://github.com/IGITUGraz/eligibility_propagation), [BSD-style three-clause license](https://github.com/IGITUGraz/eligibility_propagation/blob/master/LICENSE).

Each agent can own its synapses, adaptation state, eligibility traces and learning signals. However, reward construction, sensory encoding and action decoding still need design. Traces fade; they are not durable meal memories. Porting the reference TensorFlow 1.14–1.15/Python 3.6–3.7 implementation to existing PyTorch is substantial work. CPU/GPU simulation is possible in principle; dense spike simulation need not be cheaper than the current LSTM. Intel AI Boost is not the Loihi/SpiNNaker hardware discussed in this literature. No laptop energy or speed advantage is established.

### 3. CfC/NCP: small recurrent dynamics with sparse wiring

**Neural architecture.** Closed-form continuous-time networks avoid an iterative ODE solver; Neural Circuit Policies add structured sparse wiring inspired by *C. elegans*. The author library exposes PyTorch and TensorFlow cells. [CfC paper](https://doi.org/10.1038/s42256-022-00556-7), [ncps code, Apache-2.0](https://github.com/mlech26l/ncps), [release history](https://github.com/mlech26l/ncps/releases).

A compact wired CfC behind the existing encoder is a moderate replacement experiment, particularly for variable observation intervals. Every resident can have different private weights and hidden state. Continuous-time dynamics are state adaptation, not automatic weight learning: PPO or another learner remains necessary. Fixed-tick Godhood Trials may gain little, and sparse wiring does not guarantee efficient GPU execution or useful memory. The package has release/documentation infrastructure; recent commit cadence was not verified. CPU/GPU training and inference are supported by its frameworks; NPU export remains untested.

### 4. EvoTorch/MAP-Elites: diverse inherited behaviors

**Population optimization framework, not a lifetime learner.** EvoTorch offers PGPE, genetic algorithms and MAP-Elites on PyTorch. MAP-Elites maintains diverse high-performing solutions across chosen behavior descriptors instead of optimizing one winner. [Paper](https://arxiv.org/abs/2302.12600), [author code, Apache-2.0](https://github.com/nnaisense/evotorch), [maintenance releases](https://github.com/nnaisense/evotorch/releases).

This provides a practical evolutionary comparison to ALIEN, whose individual gradient learning remains unverified. Evolution can select fixed brain weights or declared plasticity/topology genes; the framework does not automatically implement topology growth. Unlike NEAT, its listed methods should not be presented as a ready-made complexifying brain.

Private evaluation worlds are possible, but population fitness and an archive pool information centrally. A centrally selected collection of policies differs from organisms reproducing locally. Inherited trained weights, inherited learning rules and fresh-child learning are three separate experiments. CPU/GPU vectorization is available; rollout cost dominates when worlds cannot batch efficiently. Integration is moderate-to-high effort, and meaningful population sizes multiply lifetime evaluations. No pretrained model is required.

### 5. RIAL without sharing: learn discrete communication independently

**Multi-agent learning algorithm.** Reinforced Inter-Agent Learning combines recurrent Q-learning with communication actions. It can use separate brains and discrete messages, making it compatible in principle with ten physical tones. [Primary paper](https://proceedings.neurips.cc/paper_files/paper/2016/file/c7635bfd99248a2cdef8249ef7bfbef4-Paper.pdf), [author code, Apache-2.0](https://github.com/iassael/learning-to-communicate).

The paper explicitly compares parameter-sharing and no-sharing variants. Independent RIAL fails on some tasks where shared parameters/differentiable communication succeed: emergent language is harder when everyone learns privately. DIAL passes gradients between agents during centralized training, so it changes the independence experiment even if deployed brains later act separately. The original examples also optimize shared utility; Godhood's private bodily consequences require an explicit adaptation.

The author code is a historical reproduction with Docker-era infrastructure, not a verified modern Windows package. Reimplementing its relevant discrete-message idea in current PyTorch is moderate effort. Physical tones already permit communication; a second policy head or simultaneous message/action channel would change the present action contract and needs a separate design. Tone frequency alone is not language evidence.

## Practical boundaries

For a first new architecture trial, CfC is the closest fit to the existing PyTorch encoder and recurrent controller interface. Continual backpropagation is a separate candidate for preserving plasticity, and independent RIAL supplies a communication-learning design to test after feeding becomes reliable. This ordering is an engineering recommendation, not a measured performance ranking. E-prop requires more porting; evolutionary search multiplies rollout cost. Combining all five at once would prevent attributing any improvement to a particular change.

All five can start with random weights. None demonstrates curiosity, farming, construction, reproduction and society as one working package. Dreamer, existing R2D2-inspired replay and NEAT remain comparisons already discussed, not new discoveries. LLM-agent orchestration organizes pretrained assistants; it does not meet this goal of learning embodied competence from scratch.

Differentiable plasticity/Backpropamine is scientifically relevant fast-memory work, but the current author repositories declare Uber Non-Commercial licenses; it is not a straightforward permissive open-source adoption. [Current license statement](https://github.com/uber-research/backpropamine#copyright-and-licensing-information).

Use existing CPU/GPU PyTorch first. No candidate has verified training on this laptop NPU. Exported inference is a separate engineering test; moving learning or changing plastic state onto the NPU cannot be assumed. Implementation effort above is an estimate; no hardware performance prediction is claimed.

Preregister fresh seeds 70131, 70142, 70153; two independent residents per seed/arm; 2,048 learning decisions each, then two held-out 12,000-tick frozen evaluations. Include initial-weight/random controls and the privileged feasibility oracle without importing its experience. Check checkpoint continuation and private data provenance.

Measure deprivation, fullness, meals, injuries, sustained safe crossings, retained/replayed eating sequences, unique state visits and action repetition. Report all lives and seed groups; this short learning budget is a mechanism screen, not promotion evidence. A separate paired communication probe should compare intact hearing with shuffled and silent tones: measure whether received tones causally change useful receiver actions and joint feeding. Do not infer communication from mutual information or frequent calls alone.

No experience, gradients or trained weights pass between residents. Shared batching is only computation. Any later shared-experience baseline must be labeled a different condition. If retention/exploration helps, confirm with the existing survival gate before trying plasticity maintenance or evolving larger populations.

## Implementation readiness: CfC and exclusive tones

Follow-up source review, October 5, 2026; recommendations only. [PyPI metadata](https://pypi.org/project/ncps/1.0.1/) pins **ncps 1.0.1**, published August 14, 2024, Apache-2.0. Its 60.3 kB platform-independent wheel has published SHA-256 `249b2a62c38608df62d454fe20f4e880f74c27ef97ea3a45e101d47b1b273fb5`. Nothing was downloaded. Reviewed author `master`/documentation source was not verified byte-identical to that wheel; a verified immutable current source commit was unavailable. Historical GitHub `v2.0.0` concerns the earlier keras-ncp lineage, not an appropriate ncps package pin. [Setup metadata](https://github.com/mlech26l/ncps/blob/master/setup.py) declares packaging/future, deliberately omits PyTorch, and the cells also import NumPy; verify existing dependencies without replacing the working PyTorch build.

The smallest integration is `CfCCell(80, 64, mode="default", backbone_layers=0)` behind the existing encoder, keeping current readout heads. It consumes features `[B,80]`, private carry `[B,64]`, and scalar elapsed time; returns output and new carry, both `[B,64]`. Start with `dt=1.0` per decision, no mixed-memory LSTM and no projection. Lifetime weight learning still comes from the existing learner. Persist carry, optimizer and RNG; reconstruct burn-in separately for online/target cells and detach only at declared training boundaries. [Author cell source](https://raw.githubusercontent.com/mlech26l/ncps/master/ncps/torch/cfc_cell.py).

Analytically derived core counts, excluding encoder/readout: no-backbone CfC **37,120** trainable parameters; `torch.nn.LSTMCell(80,64)` **37,376**; default 128-wide-backbone CfC **51,584**. Thus default constructor settings silently increase capacity. These are source arithmetic, not instantiated measurements. Wired CfC uses dense masked matrices, includes a non-trainable mask parameter, and leaves time-gate matrices dense; report trainable, stored and effectively connected counts separately. Motor-output width can also differ from total recurrent-state width. [Wired source](https://raw.githubusercontent.com/mlech26l/ncps/master/ncps/torch/wired_cfc_cell.py).

For sequences, `CfC` returns `[B,T,64]` plus `[B,64]` carry. Its reviewed wrapper squeezes supplied per-step timespans to `[B]`, while cell gates have `[B,64]`: an inferred broadcasting hazard, untested here. Use `timespans=None` initially; a direct cell can receive `[B,1]` intervals if variable timing is later validated. Elapsed decision time is a modeling choice, not a guarantee of exact physical integration. [Wrapper source](https://raw.githubusercontent.com/mlech26l/ncps/master/ncps/torch/cfc.py).

**No separate tone head is required for today's action contract.** Original RIAL separately selects simultaneous environment and message actions, hence its two heads; our mutually exclusive physical tones already inhabit one ordinary discrete action union. Keeping that union is an independent recurrent-Q communication adaptation, not an exact RIAL reproduction. Original RIAL also disables replay because co-learning partners make old experience stale. Preserve private weights/data and test shuffled/silent hearing before claiming communication. [Primary RIAL methods, section 5.1](https://proceedings.neurips.cc/paper_files/paper/2016/file/c7635bfd99248a2cdef8249ef7bfbef4-Paper.pdf).
